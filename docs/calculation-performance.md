# 计算性能与 GPU 可行性

## 已实现（2026-09-09）

计算器仍使用浏览器 CPU，积分接口与数据库保持原架构。胜率计算和牌型分布各自使用独立 Web Worker；修改选牌、人数或离开页面会终止旧胜率 Worker。计算失败会结束等待状态并提示重试。

- 牌面进入计算引擎时转换为 0–51 的整数；牌型用可直接比较的整数分数表示，对外仍返回原来的牌型数组。
- 复用计数数组和公共牌状态；用位掩码、顺子表和踢脚牌表替代字符串解析、排序和临时集合。
- 用整数索引缓存己方牌力和未来公共牌统计，避免每个蒙特卡洛样本构造、排序和拼接字符串。
- 复用 Halton 序列。条件胜率模型发现某位对手已令己方无法独赢后，跳过该样本余下的发牌维度；仍保持原样本的结果。
- 蒙特卡洛保留同一随机种子和无放回发牌顺序。发现己方已输后停止额外牌型评估，但仍完成既定洗牌与恢复，保证下一个样本一致。
- 进度按时间间隔节流。独立 Worker 不需要等待定时器，直接由 `terminate()` 取消；其他调用者仍保留协作式调度和 AbortSignal。
- 精确枚举同样使用整数评估和按时间让出执行。

没有降低 4,096 次即时模型或 500,000 次蒙特卡洛的采样量，没有改变胜、平、负、平分底池权益及条件胜率区间规则。

## 性能记录

同一台 Windows 机器、Node v24.14.0、A♠ K♥ 对 Q♠ J♥ 2♦、四名对手。新旧版本分别运行三轮，取每阶段中位数，包含第一轮 JIT 冷启动。

| 阶段 | 原实现 | 优化后 | 加速比 |
| --- | ---: | ---: | ---: |
| 牌型分布 | 352 ms | 21 ms | 16.8× |
| 4,096 次即时估算 | 46 ms | 6 ms | 7.7× |
| 翻牌后条件胜率模型 | 3,450 ms | 595 ms | 5.8× |
| 500,000 次蒙特卡洛 | 7,653 ms | 259 ms | 29.5× |
| 上述阶段中位数之和 | 11,501 ms | 881 ms | 13.1× |

这是计算函数的墙钟时间，包含函数内部调度等待，不等于浏览器从点击到渲染完成的延迟。旧版大量定时器等待也是提速来源。手机速度、浏览器定时器规则和不同牌局会影响结果；不能将该倍数推广到所有设备。

生产构建的 Worker 另在 Node 独立线程执行了消息协议集成测试：同场景从启动到完整结果约 0.97 秒，包含线程启动、消息传输、即时模型、条件模型和 50 万次模拟；此数据也不是浏览器实测。

## GPU 是否可用

**可行，但本次没有启用 GPU，也没有声称测得 GPU 加速倍数。** 当前 50 万次模拟在本机已降到几百毫秒，是否值得增加第二套实现，需要测量完整请求而非仅看着色器执行时间。

### 浏览器 WebGPU

WebGPU 的 compute shader 可以将不同样本或不同未来公共牌分配给独立调用，使用整数牌型评估，再归并胜平负与各公共牌统计。它使用访问者自己的 GPU；另一台手机访问网页时，不会自动使用服务器或开发电脑的 RTX 3090。

WebGPU 需要安全上下文，且 MDN 仍标记为非全面可用。必须检查 `navigator.gpu`、适配器与设备获取是否成功，处理设备丢失，并保留当前 CPU Worker 回退。普通局域网 HTTP 入口不能假设支持 WebGPU。参见 [MDN WebGPU API](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API)。

接入前需要解决：

1. **样本生成**：现有 xorshift 随机流跨样本连续，不能让每个 GPU 调用简单使用同一个种子。应设计并验证独立样本流，或正确实现原序列的跳跃定位；若改变采样序列，需重新建立统计与回归基准。
2. **精度**：牌型和计数可用整数保证精确。权益包含多人平局分数，方差与误差还需要归并；不应直接以单精度原子累加替换当前计算。可以归并各平局人数的整数直方图后，由 CPU 以双精度完成权益和方差计算。WGSL 的具体数值类型与当前 JS 不同，参见 [WGSL 规范](https://gpuweb.github.io/gpuweb/wgsl/)。
3. **条件模型**：当前 Halton 偏移使用 JS 双精度。直接用 WGSL 单精度实现可能改变发牌索引，不能当作逐位兼容替换。
4. **总耗时**：记录冷启动编译、上传、执行、读回和结果构建；测试桌面独显、集显和手机。只有完整请求确实更快才启用 GPU，小任务保留 CPU。
5. **取消与故障**：按批次提交，丢弃过期结果，释放缓冲区，设备不可用时重算当前请求。GPU 已提交工作不能简单等同于可立即取消的 CPU Worker。

更适合验证 GPU 的工作负载包括千万级采样、批量起手牌校准、多场景并行分析；这只是工程判断，尚无本项目 GPU 基准支持。

### 共享本机显卡的服务端计算

本机检测到 RTX 3090。若希望手机或其他设备利用它，需要部署独立的 GPU 计算服务，由网页经 HTTP 请求服务，并处理任务队列、取消、并发和服务不可用回退。当前 Sites/Cloudflare Worker 入口不会因为改用 Rust 就自动访问这张显卡。GPU 服务是额外的部署架构，不能通过浏览器端 WebGPU 或 Rust/WASM 编译直接获得。

当前选择：交付经过正确性验证的 CPU Worker 引擎。保留现有请求/响应协议，后续若加入经过实测的 GPU 实现，可在相同协议内选择后端。
